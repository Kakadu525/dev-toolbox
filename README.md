# Dev Toolbox

**Оффлайн-набор инструментов разработчика для Windows.** Один компактный `.exe`-файл вместо двадцати вкладок с онлайн-сервисами, к которым обычно тянется рука во время работы — форматирование JSON, декодирование JWT, тестирование regex, генерация QR-кодов и многое другое, без интернета и без риска отправить чувствительные данные на сторонний сайт.

## Зачем это нужно

Разработчики каждый день пользуются десятками мелких утилит — декодировать токен, отформатировать JSON, посчитать хэш, сгенерировать UUID. Обычно для этого открывается очередная вкладка браузера с online-сервисом. У этого подхода есть три постоянные проблемы:

- **Приватность.** Вставляя в незнакомый сайт токен, кусок конфига или лог с продакшена, вы не знаете, что происходит с этими данными на сервере.
- **Оффлайн-разрывы.** Без интернета такие сервисы просто недоступны.
- **Разрозненность.** Каждый инструмент — новая вкладка, новый интерфейс, новые баннеры и реклама.

**Dev Toolbox** решает это одним приложением: все данные обрабатываются локально, на вашей машине, ничего никуда не отправляется. Один `.exe`, без установки, без интернета, без слежки.

---

## Особенности

- 🖥️ **Полностью оффлайн** — ни один инструмент не обращается к интернету для своей основной работы (HTTP Client — исключение по своей природе: это сетевой клиент, но соединения инициируете только вы сами и только туда, куда укажете)
- 📦 **Один exe-файл** — весь интерфейс встроен внутрь исполняемого файла, ничего распаковывать или доустанавливать не нужно
- ⚡ **Нативная производительность** — написано на C++20, без Electron и тяжёлых рантаймов
- 🎨 **Тёмная и светлая тема**, настраиваемый акцентный цвет и размер шрифта
- 🔒 **Приватность по умолчанию** — история буфера обмена хранится только в памяти процесса, ничего не пишется на диск без вашего ведома

## Установка и запуск

Установка не требуется. Скачайте `DevToolbox.exe` и запустите — всё остальное уже внутри файла.

> **Права администратора.** Приложение запрашивает повышенные права при старте — это нужно для полноценной работы Process Explorer (просмотр и завершение системных процессов). Без этого шага приложение всё равно откроется, но часть процессов будет недоступна для управления.

### Системные требования

- Windows 10 версии 1809 или новее (или Windows 11)
- [Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/) — как правило, уже предустановлен в современных версиях Windows

## Сборка из исходников

### Требования

- Visual Studio 2022 (или новее) с компонентом **Desktop development with C++**
- CMake 3.20+
- Git
- Подключение к интернету при первой сборке (для загрузки зависимостей)

### Шаги

```powershell
git clone https://github.com/<ваш-профиль>/dev-toolbox.git
cd dev-toolbox
```

Откройте папку проекта в Visual Studio через **File → Open → Folder** — CMake-конфигурация запустится автоматически. Дождитесь завершения (при первом запуске будут скачаны все зависимости) и соберите проект через **Build → Build All** (Ctrl+Shift+B).

Готовый `DevToolbox.exe` появится в папке сборки (`out/build/x64-Debug/` или аналогичной, в зависимости от конфигурации).

### Используемые библиотеки

Все зависимости подключаются автоматически через CMake `FetchContent` — ничего устанавливать вручную не нужно.

| Библиотека | Назначение |
|---|---|
| [Microsoft WebView2](https://developer.microsoft.com/microsoft-edge/webview2/) | Отрисовка пользовательского интерфейса (HTML/CSS/JS) внутри нативного окна |
| [nlohmann/json](https://github.com/nlohmann/json) | Работа с JSON, включая протокол обмена сообщениями между C++ и интерфейсом |
| [pugixml](https://github.com/zeux/pugixml) | Разбор и форматирование XML |
| [yaml-cpp](https://github.com/jbeder/yaml-cpp) | Разбор и форматирование YAML |
| [QR-Code-generator](https://github.com/nayuki/QR-Code-generator) | Генерация QR-кодов |
| [stb_image / stb_image_write / stb_image_resize2](https://github.com/nothings/stb) | Декодирование, кодирование и изменение размера изображений |
| [miniz](https://github.com/richgel999/miniz) | Упаковка интерфейса в архив, встраиваемый в исполняемый файл |

Помимо перечисленного, активно используется нативный Windows API: BCrypt (хэши), WinHTTP (HTTP-клиент), Toolhelp32Snapshot (Process Explorer), Clipboard API (история буфера обмена) и другие системные интерфейсы — без сторонних зависимостей там, где это уже предоставляет сама Windows.

## Архитектура

Приложение построено на модели «нативное ядро + веб-интерфейс»:

```
┌──────────────────────────────────────┐
│              DevToolbox.exe            │
│                                        │
│   WinAPI-окно ──▶ WebView2 (UI-слой)   │
│                       │ JSON-сообщения │
│                       ▼                │
│              ToolRegistry (роутер)     │
│                       │                │
│     ┌─────────────────┼──────────────┐ │
│  Base64Tool      JsonTool   ...  19 инструментов │
└──────────────────────────────────────┘
```

- **Интерфейс** — HTML/CSS/JS, отрисовывается через WebView2 (движок Microsoft Edge)
- **Логика** — полностью на C++, каждый инструмент реализует общий интерфейс `ITool`
- **Обмен данными** — простой JSON-протокол (`{tool, action, payload}` → `{status, result}`) через `PostWebMessageAsString`
- **Ассеты** — весь интерфейс на этапе сборки упаковывается в zip-архив и встраивается в исполняемый файл как ресурс, распаковываясь во временную папку при запуске

Такое разделение позволяет держать всю бизнес-логику в типобезопасном, быстром C++, а интерфейс — гибким и легко стилизуемым через обычный CSS.

---

## Приватность

- Ни один инструмент не отправляет данные в интернет, за исключением HTTP Client, который по своей природе выполняет только те запросы, которые вы явно указали
- История буфера обмена хранится исключительно в оперативной памяти процесса и полностью исчезает при закрытии приложения
- Единственный файл, сохраняемый на диске — `settings.json` с настройками интерфейса (тема, шрифт, акцентный цвет); никаких пользовательских данных в нём нет
